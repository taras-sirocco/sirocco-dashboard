**Версія:** 1.3 · актуальна
**Замовник:** Тарас Водяний, CEO Sirocco Energy
**Пристрій:** iPad Pro 12.9″, landscape основний, portrait — коректний запасний
**Стек:** Next.js (PWA) + Payload CMS + PostgreSQL, offline-first, мова — українська

Дизайн і поведінку брати з прототипів у `sirocco-prototypes/`. Цей документ —
специфікація логіки; прототипи — джерело вигляду.

---

## Ролі

- **Монтажник / бригадир** — проходять зміну. Вхід: вибір імені + 4-значний PIN.
- **Адмін (Тарас)** — Payload, керує всім контентом.

Планшет веде одна людина — відповідальний за зміну. Її ім'я тримається в рядку
статусу на всіх екранах.

---

## Екрани

### 1. Логін
Список імен великими плитками → PIN. Заголовок «Відповідальний за зміну».

### 2. Відкриття зміни
Чек-лист по одному питанню на екран, кнопки «Так» / «Ні».
**Фото на відкритті НЕ робимо** — вранці лише звірка, доказ зроблено на закритті ввечері.
«Ні» → екран «Вкажіть причину» (голос/текст) → кнопка «Повідомити про
неготовність дільниці» → термінове повідомлення Тарасу й бригадиру.
Останнє питання — прийняття робочого місця: «Так, приймаю» / «Ні».
«Так» → екран «Зміну прийнято», акцент на імені відповідального, у шапці
з'являється рядок «Зміна відкрита · Відповідальний — [ім'я]».

### 3. Хаб (головний екран зміни)
Поточна задача + прогрес по зміні. Велика кнопка «Продовжити роботу».
Плитки: «Додати нотатку до процесу», «Повідомити про критичну проблему»,
«Що змінили за вашими сигналами» (з лічильником нового), «Закрити зміну».

### 4. Задачі
Послідовна подача, НЕ канбан. Одна задача на екрані: позиція в черзі, назва,
лічильник зроблено/ціль, смуга прогресу, «Інструкція по кроках», «Готово».
«Готово» → ввід кількості степером (скільки зробив щойно) → підтвердити →
наступна незавершена задача підтягується автоматично.
Лічильник накопичувальний, перенесений залишок з минулого дня враховано.

### 5. Інструкція по кроках (TWI)
Один крок на екран: **важливий крок** (заголовок) / **ключовий момент**
(виділено) / **чому** (дрібніше) + фото/схема. Кнопки «Далі», «Назад».
Останній крок кожної деталі — **звірка з еталоном**: заголовок «Порівняй з
еталонною деталлю», текст «зроби візуальне порівняння з еталонною деталлю на
столі», дві кнопки «Так, відповідає» / «Ні, не відповідає».
Еталонну деталь роблять разом наперед, вона фізично на столі — фото еталону не
потрібне. «Ні» → запис причини + сигнал відповідальному (дефект не йде далі).

### 6. «Що завадило?»
Спрацьовує при закритті для кожної задачі з недобором (done < target),
по одній, не стосом. Картка недобору (скільки з цілі, скільки бракує),
голос/текст. Заголовок «Що завадило?», не «чому не виконали».
Залишок переноситься на завтра автоматично (поведінка за замовчуванням,
Тарас/бригадир може перебити в Payload).

### 7. Аркуш дня
Перед закриттям. Задачі з підсумком (готово / частково / не почато + скільки з
цілі). Коментарі, зібрані за день, — списком, з часом і контекстом,
**не переписувати**, можна дописати голосом/текстом.

### 8. Закриття зміни
Чек-лист. **Три пункти обов'язково з фото** (тільки камера, галерея заборонена):
акумулятори на зарядці, незавершені вузли з позначкою етапу, стіл.
Без усіх трьох фото зміна не закривається.
Окремий екран підтвердження з іменем і часом.
Після «дякую» — через 10 секунд автоперехід на екран спокою з логотипом по центру.

### 9. «Що змінили за вашими сигналами»
Окремий екран, доступний з хабу. Записи: дата · що сказали · що зробили.
Наповнюється в Payload. Без нього коментарі стають ящиком скарг.

### 10. Нотатка / критична проблема
Один екран, два режими. Нотатка — нейтральна, «в звіт дня». Критична —
червоний мікрофон, «терміновий сигнал одразу». Голос основний, текст і
фото/відео додатково. Контекст (задача, крок, час, хто) записується автоматично.

### 11. Модальні повідомлення та задачі (від Тараса / бригадира)
На весь екран поверх усього, не закриваються нічим окрім кнопки підтвердження.
- **Повідомлення** — світло-сірий фон, кнопка «Прочитано». До відома.
- **Нова задача** — жовтий фон, кнопка «Прийнято». Змінилась робота на сьогодні.
Колір несе сенс, місцями не міняти. Фіксувати час показу і час підтвердження.
Офлайн → показати після відновлення зв'язку. Якщо людина була в кроці інструкції
— після підтвердження повернути рівно туди. Кілька непідтверджених — по черзі.

## Наскрізні елементи

- Верхня смуга: лого (плейсхолдер поки), час+дата, індикатор мережі
  (зелений/червоний, без тексту).
- Рядок статусу зміни під шапкою на всіх екранах після відкриття.
- Кнопки нотатки і критичної проблеми доступні протягом усієї роботи.
- Клікабельні цілі не менші 60×60 px — під рукавички.

## Модель даних (Payload)

```
users            id, name, pinHash, role (worker|foreman|admin), active

shifts           id, date, responsibleUserId, openedAt, closedAt,
                 handoverOk, handoverNote

checklistTemplates  id, type (opening|closing), version, items[]
  item:          key, text, requiresPhoto, order

checklistRuns    id, shiftId, templateId, templateVersion, completedAt
checklistAnswers id, runId, itemKey, status (ok|problem), photoId, note, answeredAt

tasks            id, date, title, stageNo, targetQty, order, carriedFromTaskId
taskProgress     id, taskId, shiftId, userId, qtyDelta, createdAt, unitIds (null поки)
                 ↑ інкременти, не одне число — щоб додати unitIds без переписування

procedures       id, taskId, referenceNote, steps[]
  step:          n, title, keyPoint, why, mediaUrl

blockers         id, taskId, shiftId, userId, text, audioUrl, transcript, media[],
                 qtyDone, targetQty, kind (gap|not_ready|critical|defect), createdAt

comments         id, shiftId, userId, createdAt, text, audioUrl, transcript,
                 contextType, contextId, media[]

media            id, url, type, takenAt, shiftId, source

changesLog       id, date, whatWasSaid, whatChanged

broadcasts       id, kind (message|task), body, extra, taskId, createdBy, createdAt
broadcastAcks    id, broadcastId, userId, shownAt, ackedAt

uiStrings        id, key, value    ← ВСІ тексти інтерфейсу
```

`checklistAnswers` зберігають `templateVersion` — інакше історія непорівнювана
після першої правки шаблону.

## Вимога: ВСІ тексти редагуються через адмінку

Жодного захардкодженого тексту в компонентах. Кожен рядок — з `uiStrings` за
ключем (`login.title`, `opening.done_button`, `closing.confirm` тощо),
згруповано за екранами. Fallback: нема рядка → показати ключ, не падати.
Контентні тексти (задачі, кроки, чек-листи, changesLog) — у своїх колекціях.

## Вимога: дуже зручне додавання задач

Задача + її процедура + кроки — в одному місці (Payload array fields, не три
колекції). Кроки: кнопка «+ крок», drag-to-reorder, дублювання, видалення.
Три текстові поля з ясними підписами + фото на кожному кроці. Дублювання цілої
задачі як шаблону. Черга задач — drag-and-drop, не ручні числа.
