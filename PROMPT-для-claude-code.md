# Завдання для Claude Code: планшетний застосунок складальної дільниці Sirocco

## Контекст

Я — CEO Sirocco Energy (виробництво компактних вітротурбін). Ми запускаємо
складальну дільницю: 2–4 монтажники без досвіду, 1 зміна, 1 бригадир.
Потрібен планшетний застосунок, який веде працівника через зміну: відкриття →
задачі з покроковими інструкціями → аркуш дня → закриття. Плюс адмінка, де я
керую всім контентом.

У цій папці:
- `sirocco-prototypes/` — 7 готових HTML-прототипів екранів із фінальним
  дизайном і логікою. Це референс. Дизайн і поведінку бери звідти.
- `sirocco-prototypes/README.md` — дизайн-токени і опис кожного екрана.
- ТЗ (окремий md-файл, якщо поклав) — повна специфікація.

**Спочатку прочитай усі прототипи і README. Дизайн уже затверджений — не
вигадуй свій, відтворюй цей.**

## Пристрій і адаптація — критично

Основний і єдиний робочий пристрій — **iPad Pro 12.9″ у горизонтальній
орієнтації** (1366×1024 логічних точок). Уся дизайн-адаптація в першу чергу під
цей розмір і формат.

Але планшет можуть повернути, тому:
- горизонталь (landscape) — основний, вилизаний режим;
- вертикаль (portrait) — має якісно адаптуватися, нічого не ламається, не
  обрізається, кнопки лишаються великими;
- верстка гумова (responsive), не фіксовані піксельні розміри під один екран.

Прототипи зроблені під вузький мобільний екран — при перенесенні розтягни
композицію під ширину iPad: у landscape використовуй горизонтальний простір
(двоколонкові розкладки де доречно), не залишай усе вузькою колонкою по центру.

## Технічний стек

- **Next.js** (App Router), PWA — встановлюється на iPad як застосунок, без App Store.
- **Payload CMS** — адмінка і бекенд-модель, у тому ж застосунку (Payload 3 
  вбудовується в Next.js).
- **PostgreSQL** — база.
- **Offline-first обов'язково**: уся зміна проходиться без мережі (IndexedDB +
  черга синхронізації). Фото стискаються локально перед вивантаженням. Індикатор
  стану мережі видимий, але ніколи не блокує роботу.
- Транскрипція голосу — Whisper API (винеси ключ у env, поки можна заглушку).
- Мова інтерфейсу — українська.

## Ролі

- **Монтажник / бригадир** — проходять зміну на планшеті. Вхід: вибір імені +
  4-значний PIN. Без пошти й паролів.
- **Адмін (я)** — Payload-адмінка, керує контентом. Окремий вхід.

## Екрани застосунку (з прототипів)

1. Логін — вибір відповідального за зміну + PIN.
2. Відкриття зміни — чек-лист «так/ні» по одному питанню; «ні» веде на екран
   причини з голосом/текстом → термінове повідомлення. Наприкінці — прийняття
   робочого місця. **Фото на відкритті НЕ робимо.**
3. Хаб (головний екран зміни) — поточна задача, прогрес, кнопки: продовжити
   роботу, нотатка, критична проблема, «що змінили», закрити зміну.
4. Задачі — послідовна подача (НЕ канбан), одна задача на екрані, лічильник
   зроблено/ціль, ввід кількості степером, автоперехід до наступної.
5. Інструкція по кроках — формат TWI: важливий крок / ключовий момент / чому +
   фото/схема. Останній крок — звірка з еталонною деталлю: текст «порівняй з
   еталоном» і дві кнопки «так, відповідає» / «ні, не відповідає». «Ні» → запис
   причини + сигнал відповідальному (дефект не йде далі).
6. «Що завадило?» — спрацьовує на закритті для кожної задачі з недобором
   (done < target). Голос/текст, залишок автоматично переноситься на завтра.
7. Аркуш дня — задачі з підсумком; коментарі, зібрані за день (НЕ переписувати,
   лише показати з часом і контекстом), можна дописати.
8. Закриття зміни — чек-лист, **три пункти обов'язково з фото** (тільки камера,
   галерея заборонена): акумулятори, незавершені вузли, стіл. Без усіх фото
   зміна не закривається. Окремий екран підтвердження з іменем і часом. Після
   «дякую» — через 10 секунд автоперехід на екран спокою з логотипом.
9. «Що змінили за вашими сигналами» — окремий екран: дата, що сказали, що зробили.
10. Нотатка / критична проблема — один екран, два режими (нейтральний і
    червоний терміновий). Голос основний, текст і фото/відео додатково.
11. Модальні повідомлення й задачі — на весь екран поверх усього, не закриваються
    нічим окрім кнопки підтвердження. Повідомлення: світло-сірий фон, кнопка
    «Прочитано». Нова задача: жовтий фон, кнопка «Прийнято». Фіксувати час показу
    і час підтвердження. Якщо офлайн — показати після відновлення зв'язку.

## Наскрізні елементи

- Верхня смуга: лого (плейсхолдер поки), час, дата, індикатор мережі
  (зелений/червоний, без тексту).
- Після відкриття зміни — рядок статусу «Зміна відкрита · Відповідальний — [ім'я]»
  на всіх екранах зміни.
- Кнопки нотатки й критичної проблеми доступні протягом усієї роботи (на хабі й
  на екранах задач).
- Усі клікабельні цілі не менші за 60×60 px — під рукавички.

## Модель даних (Payload-колекції)

```
users            id, name, pinHash, role (worker|foreman|admin), active

shifts           id, date, responsibleUserId, openedAt, closedAt,
                 handoverOk (bool), handoverNote

checklistTemplates  id, type (opening|closing), version, items[]
  item:          key, text, requiresPhoto (bool), order

checklistRuns    id, shiftId, templateId, templateVersion, completedAt
checklistAnswers id, runId, itemKey, status (ok|problem), photoId, note, answeredAt

tasks            id, date, title, stageNo, targetQty, order, carriedFromTaskId
taskProgress     id, taskId, shiftId, userId, qtyDelta, createdAt, unitIds (null поки)

procedures       id, taskId, steps[]
  step:          n, title, keyPoint, why, mediaUrl
  + referenceNote (текст інструкції звірки з еталоном)

blockers         id, taskId, shiftId, userId, text, audioUrl, transcript,
                 media[], qtyDone, targetQty, kind (gap|not_ready|critical), createdAt

comments         id, shiftId, userId, createdAt, text, audioUrl, transcript,
                 contextType, contextId, media[]

media            id, url, type, takenAt, shiftId, source

changesLog       id, date, whatWasSaid, whatChanged
                 (для екрана «Що змінили за вашими сигналами»)

broadcasts       id, kind (message|task), body, extra, taskId, createdBy, createdAt
broadcastAcks    id, broadcastId, userId, shownAt, ackedAt

uiStrings        id, key, value   ← ВСІ тексти інтерфейсу (див. нижче)
```

Важливо: `taskProgress` веди як інкременти (записи «+3»), а не одне число —
щоб потім додати `unitIds` без переписування схеми.
`checklistAnswers` зберігають `templateVersion` — інакше історія стане
непорівнюваною після першої правки шаблону.

## Вимога 1: ВСІ тексти редагуються через адмінку

Це критично. Я маю могти змінити **будь-який текст** на платформі, не чіпаючи код:
- заголовки, підзаголовки, підписи кнопок на кожному екрані;
- пункти чек-листів відкриття й закриття;
- назви задач, тексти кроків інструкцій (важливий крок / ключовий момент / чому);
- інструкцію звірки з еталоном;
- тексти повідомлень і задач;
- записи «що змінили за вашими сигналами»;
- підказки, плейсхолдери, службові написи.

Реалізуй так: **жодного захардкодженого тексту в компонентах.** Кожен рядок
береться з колекції `uiStrings` за ключем (напр. `login.title`,
`opening.done_button`, `closing.confirm`). У Payload зроби зручний редактор
цих рядків, згрупований за екранами (група в назві ключа: `login.*`,
`opening.*`, `task.*` тощо), щоб я легко знаходив потрібне. Дай fallback: якщо
рядок відсутній — показувати ключ, не падати.

Контентні тексти (задачі, кроки, чек-листи, changesLog) редагуються у своїх
колекціях, а не в uiStrings — це вже дані, не інтерфейс.

## Вимога 2: дуже зручне додавання задач

Це головне в адмінці. Структура задачі:
- **Задача** = назва + етап (stageNo) + ціль у штуках (targetQty) + порядок у черзі.
- До задачі прив'язана **процедура** = впорядкований список **кроків**.
- Кожен **крок** = важливий крок (заголовок) + ключовий момент + чому + фото/схема.
- Плюс інструкція звірки з еталоном для всієї процедури.

Зроби створення задачі максимально зручним:
- Створення задачі й її процедури — **в одному місці, на одному екрані**, не в
  трьох різних колекціях, між якими треба стрибати. Використай Payload
  вкладені масиви (array field) для кроків прямо всередині задачі/процедури.
- **Кроки додаються кнопкою «+ крок»**, легко міняються місцями (drag-to-reorder),
  дублюються, видаляються.
- На кожному кроці — три текстові поля з ясними підписами українською («Важливий
  крок», «Ключовий момент», «Чому це важливо») і завантаження фото.
- Дай можливість **дублювати цілу задачу** як шаблон для наступної (щоб схожі
  етапи не набивати з нуля).
- Черга задач на день — сортування drag-and-drop, а не ручне проставляння чисел.
- Живий прев'ю: як крок виглядатиме на планшеті (не обов'язково, але дуже бажано).
